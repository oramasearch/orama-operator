# v0.7.2

**Released:** 2026-10-20 · **Branch:** `main` · **Previous:** [v0.7.1](v0.7.1.md) (2026-10-20).

v0.7.2 is **a patch that moves the operator's copy of Lake's schema through `0090_billing_contacts`**,
so lake v0.3.1, which adds billing contacts, can roll. Nothing else changes.

| Measured | Value |
|---|---|
| Since v0.7.1 | the vendored schema, v0.7.1's leaf versions and back-merge |
| Resource kinds | 43 (unchanged); no CRD change |
| Lake schema | lake `dev` at `2b39c2f73145d79f4267d12529d7e2d1c76a6090`, SHA-256 `93e4e099f7520187cce521bd97af243233c5fd27cb5cf397b38311d6c442d539`, through `0090_billing_contacts` |
| Tests | see [Verification](#verification) |

## What changes on the roll

Each Lake's `controldb-schema` Job runs again and applies `0090_billing_contacts`: the
`billing_contacts` table and `billing_contacts_guard`, additive. The restore rehearsal also counts
`billing_contacts_guard`. Lake images before v0.3.1 ignore the table. See
[`docs/lake/schema.md`](../lake/schema.md).

## What it does not include

Everything under [v0.7.1](v0.7.1.md)'s *does not include*.

## Known issues

Unchanged from [v0.7.1](v0.7.1.md#known-issues), including the manager's occasional OOMKill at
start-up on a management cluster with many resources.

## Verification

Run on the release branch, macOS arm64, with the Kubernetes 1.30.3 envtest binaries and a local
Postgres: `go build`, `go vet`, `gofmt -l` (nothing), `make manifests generate` (no diff),
`helm lint chart` (0 failed); `go test ./... -count=1` with the Lake schema, order and control DB
Postgres tests: **834 test functions, 822 passed, 12 skipped, 0 failed** (827 subtests passed). The
skipped are the opt-in Postgres stores without their switches, the zetta-tunnel egress test and the
live chart download. `TestLakeSchemaEnvtest` applied the new schema through 0090 and
`hack/check-lake-schema.py` confirmed the vendored bytes.

On upgrade, each Lake's `controldb-schema-migrate` Job runs and completes on schema 0090, after
which lake v0.3.1 may roll.

The image built from the tag is published as `oramasearch/orama-operator:v0.7.2` (there is no
`latest`), and the chart as `0.7.2` in `oramasearch/orama-operator-chart`.
