# v0.10.2

**Released:** 2026-10-25 · **Branch:** `main` · **Previous:** [v0.10.1](v0.10.1.md) (2026-10-25).

A patch with two fixes: an app's **Zetta binding is the JSON document app-runtime reads**, so apps with workspace
data start again, and Cloud v1 stacks **generate their DISCO and pgAdmin credentials** and replace the
placeholder RabbitMQ admin password.

| Measured | Value |
|---|---|
| Resource kinds | 49 CRDs in `chart/crds` (unchanged) |
| CRD changes | none |
| Lake schema | unchanged |
| Tests | see [Verification](#verification) |

## What it includes

- **An app's Zetta binding is a JSON document.** The binding Secret's `zetta` key held the bare token;
  app-runtime reads the file with `json.loads` and needs `{"lake_url":…,"customer_id":…,"token":…}`, so
  every app with workspace data crash-looped at startup. The operator now writes that document, on the
  synchronized and the standalone path; `lake_url` is the pod's `LAKE_URL`. A byte-for-byte fixture
  (`internal/controller/testdata/app-binding-zetta.json`) is shared with app-runtime. The token and the
  hashes Lake registers are unchanged.
- **Cloud v1: the remaining generated credentials.** Bootstrap creates `<cr>-disco-auth` (`DISCO_SECRET`,
  read by DISCO and workers, and by index-builder as `DISCO_SECRET_KEY`) and `<cr>-pgadmin-auth`
  (`PGADMIN_DEFAULT_PASSWORD`), 48-character hex, generated once and kept across disable and re-enable.
  Real values already in the old component Secrets are adopted (conflicting real DISCO copies stop
  bootstrap, naming where they are, without values); only the exact former placeholders are replaced and
  pruned. The exact legacy RabbitMQ admin placeholder password is replaced once; real broker passwords
  are kept. The same on every cluster, with no chart value or flag.

## Upgrading

**No CRD changes.** Roll as for every release: CRDs widened, then `helm upgrade`, then CRDs exactly
([`../operations/crd-rollout.md`](../operations/crd-rollout.md)).

**What restarts, once, on the first reconcile after the roll:**

- **Every Lake app with a Zetta binding**: the binding's bytes change, so its credential digest does, and
  the app's pod rolls once.
- **Cloud v1 stacks**: DISCO, workers and index-builder (the new `<cr>-disco-auth` hash), pgAdmin
  (`<cr>-pgadmin-auth`), and the broker StatefulSet where its admin password was the legacy placeholder.
  Later reconciles change no credential. On a production stack, confirm the set and its members are
  `Ready` afterwards.

Nothing else changes in what the operator renders.

## What it does not include

- Routing the Ingress to lake's proxy port: it waits until every Lake runs lake v0.7.x, which has the
  proxy listener.
- The changes held back in [v0.9.0](v0.9.0.md#what-it-does-not-include).

## Known issues

- **Neither fix had run on a cluster when the release was cut.**
- app-runtime's `workspace.sql()` calls `/zetta/v1/sql`, which Lake does not serve on the workspace
  route. An app that queries with SQL starts with this release, then fails on its first query. A lake
  change, not an operator one.
- Otherwise unchanged from [v0.10.0](v0.10.0.md#known-issues).
