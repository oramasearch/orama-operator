# v0.11.2

**Released:** 2026-10-30 · **Branch:** `main` · **Previous:** [v0.11.1](v0.11.1.md) (2026-10-29).

A patch release: **observability agents write their alert routing before Pixie's release exists**, so nonprod alerts
reach Slack `#monitoring-stg` and production alerts `#monitoring` without waiting for the Pixie images
([#455](https://github.com/oramasearch/orama-operator/issues/455)).

| Measured | Value |
|---|---|
| Resource kinds | 54 CRDs in `chart/crds` (unchanged) |
| CRD changes | none |
| Lake schema | nothing vendored |
| Tests | see [Verification](#verification) |

## What it includes

| PR | Change |
|---|---|
| [#1070](https://github.com/oramasearch/orama-operator/pull/1070) | Two defects that kept every `ObservabilityAgent` Pending once the hubs and agents were applied (#1068, #1069). **Leaf clients know Orama's kinds:** the client for a leaf cluster was built with Kubernetes' types only, so the nonprod agent's read of the hub's `PixieCloud` failed with `no kind is registered`; it now uses a scheme with Kubernetes' and Orama's types. **The agent creates the hub's `plc` namespace:** the hub creates it only once Pixie's release exists, so the production agents failed with `namespaces "plc" not found`; the agent now applies it with the hub's own labels, Pod Security level (`baseline`) and field owner |

Since v0.11.1, `dev` also holds `config/clusters/` YAML: every leaf on v0.11.1; the nonprod observability hub and agent
([#1068](https://github.com/oramasearch/orama-operator/pull/1068)); production's hub on the management cluster and agents on
`orama-production-cluster-02` and `-03` ([#1069](https://github.com/oramasearch/orama-operator/pull/1069)), alerting to Slack.

## What it does not include

- Pixie itself: its build and the private image mirrors ([#455](https://github.com/oramasearch/orama-operator/issues/455)).
  The hubs stay Pending on Pixie's release.

## Upgrading

- No CRD changes. The CRD rollout ([crd-rollout.md](../operations/crd-rollout.md)) runs as for any release and changes nothing.
- **What rolls on each cluster:** the operator, and the zetta-tunnel mesh pods, which carry a container from the operator
  image. No Lake or Cloud v1 workload changes.
- On the managing cluster, the production agents create the empty namespace `plc`.

## Known issues

- Unchanged from [v0.11.1](v0.11.1.md#known-issues).
