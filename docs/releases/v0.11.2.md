# v0.11.2

**Released:** 2026-10-30 · **Branch:** `main` · **Previous:** [v0.11.1](v0.11.1.md) (2026-10-29).

A patch release: **observability agents write their alert routing before Pixie's release exists**, so nonprod and
production alerts reach their Slack channels without waiting for the Pixie images.

## What it includes

Two defects that kept every `ObservabilityAgent` Pending once the hubs and agents were applied:

- **Leaf clients know Orama's kinds.** The client for a leaf cluster was built with Kubernetes' types only, so a nonprod
  agent's read of the hub's `PixieCloud` failed with `no kind is registered`; it now uses a scheme with Kubernetes' and
  Orama's types.
- **The agent creates the hub's `plc` namespace.** The hub creates it only once Pixie's release exists, so production
  agents failed with `namespaces "plc" not found`; the agent now applies it with the hub's own labels, Pod Security
  level (`baseline`) and field owner.

## What it does not include

- Pixie itself: its build and the image mirrors. The hubs stay Pending on Pixie's release.

## Upgrading

- No CRD changes. The CRD rollout ([crd-rollout.md](../operations/crd-rollout.md)) runs as for any release and changes nothing.
- **What rolls on each cluster:** the operator, and the zetta-tunnel mesh pods, which carry a container from the operator
  image. No Lake or Cloud v1 workload changes.
- On the managing cluster, the production agents create the empty namespace `plc`.

## Known issues

- Unchanged from [v0.11.1](v0.11.1.md#known-issues).
