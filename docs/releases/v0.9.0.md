# v0.9.0

**Released:** 2026-10-23 · **Branch:** `main` · **Previous:** [v0.8.0](v0.8.0.md) (2026-10-22).

v0.9.0 carries the operator side of zetta v0.5.0 — **every workspace Zetta gets the approved connector
destinations it needs** — plus nonprod Stripe payments per environment, the Cloud v1 production
dashboard credentials, the qualified HPES image and an optional Ably reference for index-builder.

## Before it rolls

- **Roll this operator before zetta v0.5.0.** zetta v0.5.0 dials an in-cluster connector source only
  when `ZETTA_CONNECTOR_ALLOW_DESTINATIONS` lists it; until this operator has rendered the variable,
  a workspace Zetta on v0.5.0 refuses lake's SQLite/DuckDB/Polars services and in-cluster Postgres.
- **Workspace Zettas restart once** when the variable first appears in their `OramaZettaCluster`
  `spec.env`, and again when a workspace adds or removes a service (seen within about 60 seconds).
- **Apply the set files after the roll, with Steve's consent:** `lake-nonprod` (#887's Stripe sources;
  all nine source Secrets exist), `v1-prod` (#888, #889) and `v1-nonprod` (#889, #892). Merging them
  changed no cluster.
- The Lake schema is unchanged, so lake v0.4.0 keeps running. **The next lake release** (with
  migrations `0094`–`0098`) needs an operator release that vendors its schema first.
