# v0.9.0

**Released:** 2026-10-23 · **Branch:** `main` · **Previous:** [v0.8.0](v0.8.0.md) (2026-10-22).

v0.9.0 carries the operator side of zetta v0.5.0 — **every workspace Zetta gets the approved connector
destinations it needs** — plus Stripe payments per nonprod environment, prepared Cloud v1 dashboard
credentials, and an optional Ably reference for index-builder.

> **Read [Before it rolls](#before-it-rolls).** This operator must roll before the zetta v0.5.0 image
> reaches any workspace Zetta.

## Features and fixes

- **Connector destinations for workspace Zettas.** Every workspace Zetta gets
  `ZETTA_CONNECTOR_ALLOW_DESTINATIONS`, the exact `host:port` of each in-cluster service its workspace
  owns (CNPG Postgres, TiDB, lake's SQLite/DuckDB/Polars), derived from the Lake's own resources; empty
  when it has none; set only by the operator. Needed by zetta v0.5.0.
- **Stripe per nonprod environment.** Each nonprod Lake (dev, testing, staging) gets its own Stripe
  sandbox source and typed test payments, because a Stripe signing secret belongs to one endpoint.
- **Cloud v1 dashboard credentials.** A Cloud v1 dashboard can be given its restricted live Stripe key,
  cron bearer, webhook signing value, Google and Groq keys and `PRIVATE_API_KEY` from Secrets.
- **Ably for index-builder.** Optional `components.ingestion.ablyKeySecretRef`: index-builder can read
  `ABLY_API_KEY` from a Secret, checked before the Deployment changes and rolled on rotation.

## Before it rolls

- **Roll this operator before zetta v0.5.0.** zetta v0.5.0 dials an in-cluster connector source only
  when `ZETTA_CONNECTOR_ALLOW_DESTINATIONS` lists it; until this operator has rendered the variable,
  a workspace Zetta on v0.5.0 refuses lake's SQLite/DuckDB/Polars services and in-cluster Postgres.
- **Workspace Zettas restart once** when the variable first appears in their `OramaZettaCluster`
  `spec.env`, and again when a workspace adds or removes a service (seen within about 60 seconds).
- The Lake schema is unchanged, so lake v0.4.0 keeps running. **The next lake release** (with
  migrations `0094`–`0098`) needs an operator release that vendors its schema first.

## What it does not include

- Zone-level origin pulls, the base model on every workspace volume, pinned installs, AKS workload
  identity and manager workload grants: each is for a later release.
- Per-launch agent tokens: replaced by a proxy service in lake.
