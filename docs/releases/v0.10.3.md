# v0.10.3

**Released:** 2026-10-25 · **Branch:** `main` · **Previous:** [v0.10.2](v0.10.2.md) (2026-10-25).

A patch with one fix: the **Cloud v1 writer embeds 64 texts per batch, not 50,000**, so a CPU writer's memory
stays bounded during a bulk copy, where it had been OOM-killed.

| Measured | Value |
|---|---|
| Resource kinds | 49 CRDs in `chart/crds` (unchanged) |
| CRD changes | none |
| Lake schema | unchanged |
| Tests | see [Verification](#verification) |

## What it includes

- **The Cloud v1 writer embeds 64 texts per batch.** The engine's `embedding_queue_limit` drops from
  50,000 (a value sized for a GPU writer) to 64, in the writer's config and in the readers' local writer
  side, through one named constant, `writerEmbeddingBatch`. A batch's working memory grows with the
  number of texts, and at 50,000 the writer took every queued text of a collection into one batch: a CPU
  writer reached 12.5 GB at a 12Gi limit and 16.7 GB at 16Gi, and was OOM-killed each time, losing
  uncommitted writes. 64 keeps a batch to a few hundred MB, and the setting is also the queue in front of
  the writer, so a copy runs at the writer's pace. The same value on every cluster.

## Upgrading

**No CRD changes.** Roll as for every release: CRDs widened, then `helm upgrade`, then CRDs exactly
([`../operations/crd-rollout.md`](../operations/crd-rollout.md)).

**What restarts, once, on the first reconcile after the roll:** every Cloud v1 stack's **writer and readers**,
because their rendered engine config changes. On a production stack, confirm the set and its members are
`Ready` afterwards, and that the writer and readers restarted once and not again. Pause any bulk copy into a
stack until this roll has reached it.

Nothing else changes in what the operator renders.

## What it does not include

- Routing the Ingress to lake's proxy listener: unblocked now that lake v0.7.1 has it, but not yet in a
  release.
- The changes held back in [v0.9.0](v0.9.0.md#what-it-does-not-include).

## Known issues

- **The fix had not run on a cluster when the release was cut.** Its live proof is a bulk copy completing
  with the writer staying within its limit.
- Otherwise unchanged from [v0.10.2](v0.10.2.md#known-issues).
