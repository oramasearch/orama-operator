# v0.11.11

**Released:** 2026-10-31 · **Branch:** `main` · **Previous:** [v0.11.10](v0.11.10.md) (2026-10-31).

A patch release: **the Pixie UI can run scripts.** Signed in and with scripts loaded, running `px/cluster` failed with
*"Server error, http status code: 0"*. Envoy serves gRPC-web on the proxy's port 4444, and its CORS allowed only upstream's
`dev.withpixie.dev`, so the browser's preflight for `ExecuteScript` got 403. The release also makes **a configuration change roll
the pods that read it**: v0.11.10's script bundle URL reached the API server but not the proxy, which kept serving the old one.

## What it includes

- Envoy's CORS origin becomes the hub's `domain` (suffix, so `work.<domain>` is covered); rendering fails if the vendored
  origin ever disappears.
- `orama.cloud/pixie-config` on every Pixie pod template is a hash of the rendered ConfigMaps it reads, so a change rolls
  exactly those pods.
- Tests: `TestPixieCloudRendersNoUpstreamDomain` (no rendered object names `withpixie.dev`, `withpixie.ai`, `px.dev` or
  `gcr.io/pixie-oss`) and `TestPixieConfigChangeRollsThePodsThatReadIt`.

## What it does not include

- Any change to the platform charts, Lake or Cloud v1.
- A fix for the hub Prometheus not reaching production leaves.

## Upgrading

- No CRD changes.
- **Every Pixie pod restarts once**: each hub and each agent, because each pod template gains the fingerprint. Pixie keeps
  its traces in memory, so each node's recent trace data is lost. No Lake or Cloud v1 workload changes.
- People reaching the UI forward the proxy's port **4444** too (script runs), as well as 443.

## Known issues

- `ObservabilityClusterUnreachable` fires falsely for production leaves.
- kuberesolver 401 log noise on the hub's servers.
- Licensing: Pixie's eBPF programs are GPL-2.0.
