# v0.10.1

**Released:** 2026-10-25 · **Branch:** `main` · **Previous:** [v0.10.0](v0.10.0.md) (2026-10-24).

A patch: **versions as columns** on `LakeSet` and `Lake`, so `kubectl get` and Lens's list views show which
version each environment runs, without opening the YAML.

| Measured | Value |
|---|---|
| Resource kinds | 49 CRDs in `chart/crds` (unchanged) |
| Lake schema | unchanged |
| Tests | see [Verification](#verification) |

## What it includes

- `LakeSet` gets **`status.versions`**: each member and what it runs, shortened to the image tag
  (`dev=dev-aa9fefd5, staging=v0.7.0, testing=v0.7.0`; a digest reference keeps its digest; members with
  no version yet are left out). It is filled on every pass and shown as the **`Versions`** column.
  `Lake` shows **`Image`** (`spec.image`), **`Version`** and **`Revision`** (`status.imageManifest`, what
  the image reports through `lake manifest`) as columns. `OramaCloudV1Set` shares the set status, so it
  carries the field too, with no column.

**Upgrading:** the CRD changes are additive (one optional status field and new printer columns). Roll the CRDs
widened, then `helm upgrade`, then exactly, as for every release ([`../operations/crd-rollout.md`](../operations/crd-rollout.md)).
Nothing else changes in what the operator renders, so no Lake, Zetta or Cloud v1 workload restarts.

## What it does not include

- Routing the Ingress to lake's proxy port (held, see [v0.10.0](v0.10.0.md#not-in-this-release)).
- A column for `OramaCloudV1Set`'s versions.
