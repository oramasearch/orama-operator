**Released:** 2026-10-29 · **Branch:** `main` · **Previous:** [v0.10.6](v0.10.6.md) (2026-10-27).

A minor release: **five new kinds for observability**, **zone-level authenticated origin pulls** for Lake's Cloudflare
zones, and four Cloud v1 fixes for problems found on `v1-eu` after the cutover.

- Production's observability hub on the management cluster, with no `prod-support` cluster

## Upgrading

- **CRDs in two steps around the roll** ([crd-rollout.md](../operations/crd-rollout.md)): widened before the operator
  starts, exact once it alone runs. All changes are additive.
- **What rolls on each cluster:** every Cloud v1 stack on the combined image restarts its readers once, one pod at a
  time (#1053). The writers don't restart, except a writer crash-looping on an old image, which is replaced (#1036).
  The engine Ingresses and the dashboard network policies change in place.
- **Zone origin pulls wait for a permission.** The Cloudflare token needs Zone > SSL and Certificates > Edit on the zone.
  Until it has it, `ZoneOriginPulls` names the missing permission and the zone stays on global pulls. The `LakeSet` on
  the managing cluster makes and copies the zone CA Secrets once the managing cluster runs this release.

## Known issues

- **Nothing in this release has run on a cluster yet.** There was no `dev-<sha>` operator build of these merges on the
  dev environment first; Steve cut the release and named it minor on 2026-10-29, and it goes to the nonprod cluster
  first.
- [#1058](https://github.com/oramasearch/orama-operator/issues/1058): the zone switch probes a wildcard record under one
  name, not through each App's own Ingress. An App whose reconcile is stuck before its edge step could refuse Cloudflare
  after the switch.
- [#1060](https://github.com/oramasearch/orama-operator/issues/1060): with `400m`, ingress-nginx buffers large writer
  bodies to its pod's disk; the Cloudflare plan's upload cap applies before nginx.
- `kubectl diff -R -f config/clusters/` shows the two observability platform releases until they are applied.
- Otherwise unchanged from [v0.10.4](v0.10.4.md#known-issues), less #1036, which this release fixes.
