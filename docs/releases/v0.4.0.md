# v0.4.0

**Released:** 2026-10-17 · **Branch:** `main` · **Previous:** [v0.3.0](v0.3.0.md) (2026-10-17).

v0.4.0 is **every Lake runs every feature**. The per-feature switches on `Lake` are gone, and the
operator supplies a default for every image a Lake runs, with the nine library agents and
`agent-runtime` at their released `v0.1.0`. A Lake's Clerk instance is kept configured from its
secret key, a Lake's own Zetta becomes its deployment control plane in lake's row format, and the
operator's CRDs are applied in two steps around a roll so a removed field never reaches the
operator still running.

Everything in [v0.3.0](v0.3.0.md) is still here. This page lists what is new or changed.

## 1. Every Lake runs every feature

- **Removed from the `Lake` CRD:** `spec.workspaces.enabled`, `spec.services.enabled`,
  `spec.apps.enabled`, `spec.builds.enabled` and `spec.snapshots.enabled`. Workspaces, services and
  stores, apps, builds (with methodology runs and deployments) and volume snapshots are always
  reconciled.
- **Implicit switches removed too:** agents always run on default images; methodology runs and
  builds use the default runtime and builder images when the spec names none.
- **Kept:** `ingressEnabled`, `postgres.enabled` and `zetta.enabled` (both default `true`),
  `postgres.backup.enabled` and `builds.cacheEnabled`.
- **New condition `FeaturesReady`:** `False` with reason `PostgresDisabled`, `ZettaDisabled` or
  `NoPublicHost` names every feature that cannot run. Nothing is skipped silently.
- **Apps DNS:** an empty `spec.apps.wildcard` uses the Lake's `spec.host`, so an app is
  `<app>.<lake host>`.
- **Zetta memory:** every Zetta a Lake owns gets `ZETTA_MALLOC_TRIM_THRESHOLD_BYTES=67108864` and
  `MALLOC_ARENA_MAX=2` unless its env sets the name.
- **Deployments on for every Lake**: see section 4.

## 2. Default images

remove an agent.

## 3. A Lake's Clerk instance

- **`Lake.spec.clerk.secretKeySecretRef`** names a Secret in the Lake's namespace holding one Clerk
  instance's `secretKey`. With it, the operator uses Clerk's Backend API to keep the `lake` JWT
  template, add the Lake's origins (never removing any: instances are shared), and keep a Svix
  webhook endpoint at `https://<host>/identity/clerk-webhook`.
- **The Lake receives** an owned Secret `lake-<name>-clerk` and the reserved
  `LAKE_CLERK_PUBLISHABLE_KEY` and `LAKE_CLERK_WEBHOOK_SECRET`.
- **A production instance's DNS** is written as unproxied `CloudflareDNSRecord`s with
  `deletionPolicy: Retain`.
- **Condition `ClerkReady`** (`Configured`, `SecretKeyMissing`, `ClerkAPIError`). A Clerk failure
  never fails the Lake. A steady Lake makes no Clerk requests between hourly passes.
- **The webhook portal link's one-time token is exchanged** before Svix's Endpoint API is called.
- **A Lake without `spec.clerk` is untouched.** Clerk's Platform API is not used; the one-time
  dashboard steps are in [`docs/lake/clerk.md`](../lake/clerk.md).
- **`CloudflareDNSRecord`** gains `deletionPolicy` (`Delete` default, `Retain`), documents `TXT`,
  and always writes `proxied`, so a controller's `false` is kept. A resource that omits it still
  gets `true`.

## 4. Deployments: a Lake's own Zetta and lake's row contract

- **A Lake's own Zetta is its deployment control plane.** `lake-<name>-zetta` sets
  `provisionOperatorSchema: true`; lake gets `LAKE_OPERATOR_ZETTA_URL` and
  `LAKE_OPERATOR_ZETTA_TOKEN` pointing at it with the admin token it already holds (no new
  credential), and `LAKE_PUBLIC_HOST` from `spec.host` when `spec.env` does not state it. The Zetta
  StatefulSet is not changed; lake rolls once to take the two variables.
- **The operator schema adds lake's `environment_env` and `domains` tables.**
- **lake's `orama_control` row format is the contract.** Every `deployments`, `environment_env`
  and `domains` row is keyed by the Lake's public host and carries every column lake selects.
  Status rows repeat the desired row and are timed after it, so lake shows them.
- **`environment_env`** values reach the environment's `spec.env`.
- **`LakeEnvironment.spec.domains[]`** (`host`, `tls`) and **`status.domains[]`** (`pending`,
  `active`, `failed`): one Ingress rule per domain, and a proxied `CloudflareDNSRecord` owned by the
  environment when the Lake has `dnsSecretRef`. A tombstone removes both. The operator refuses a
  host that is not a DNS name, is the Lake's own host, or belongs to another environment of the
  same Lake.
- Detail: [`docs/lake/environments.md`](../lake/environments.md).

## 5. CRDs in two steps around a roll

- **Both install paths apply the chart's CRDs widened** by what the cluster still declares before
  the new operator starts, and **exactly** only once the new operator alone runs. A removed field is
  never pruned under the operator still reading it.
- **Leaf:** `OramaOperator` does both steps; a leaf whose CRDs already equal the chart's gets no
  write. **Managing cluster:** the roll runs `hack/crdunion`, applies, upgrades, waits for
  the rollout, then applies `chart/crds/`.
- **`cmd/crd_field_removal_test.go`** compares `chart/crds` with the last release tag. Each removal
  or type change fails until it is named, with why it is safe. This release names the five `Lake`
  switch removals. A tag on the tested commit itself is skipped, so the release's own tag passes;
  the list is cleared when `main` is merged back into `dev`.
- Detail: [`docs/operations/crd-rollout.md`](../operations/crd-rollout.md).

## 7. Orama Cloud v1

- **Airbyte removed** from the shared ConfigMap, the dashboard's dummy Secret and the dashboard and
  index-builder egress allowances. The stack no longer uses Airbyte.

## 8. Fixes

- **A renamed `CloudflareDNSRecord` deletes the record it replaced**. A 404 on delete
  counts as deleted.
- **A region picker lists the regions of one environment only:** a `LakeSet` whose labelled members
  name the same cloud region twice is refused with `RegionRepeated`.
- **Ask Orama defaults to the image that hands eval and corpus requests to their agents**,
  since moved to `v0.1.0`.

## 9. Leaf versions

- **Leaves:** `config/clusters/*/operator.yaml` pin every leaf to the same operator version, and
  move to `v0.4.0` in a separate change.

## What `v0.4.0` does **not** include

- **Zetta `v0.3.0` as the default Zetta image.** The default stays `oramasearch/zetta:main-4015ef76`.
- **`ClerkApplication` for Lakes.** Clerk's Platform API is a private beta; the dashboard steps are
  manual and documented.
- **The `LakeE2ETest` runner** that covers every Lake feature in a testing environment.
- **Geo load balancing** across regions and regional wildcard certificates.
- **A self-managed management cluster:** the management cluster is still rolled with a
  `helm upgrade`.
- **Origin TLS** for the Ingresses the operator creates.

## Known issues

- **No end-to-end release gate for Lake yet:** `LakeE2ETest` is a placeholder.
- **The zetta-tunnel ingress gateway never serves Cloud v1.**
- A Kafka service in a workspace does not start under restricted Pod Security; every service
  kind's sizing and metering is still to be verified.
- Leftover test resources from earlier builds may remain on clusters that installed them.

## Verification

Run on the release branch, macOS arm64, with the Kubernetes 1.30.3 envtest binaries:

```
go build ./...     ok
go vet ./...       ok
go test ./...      ok   cmd, internal/controller, internal/crdrollout, internal/meshprojection:
                        510 test functions, 497 passed, 13 skipped, 0 failed (235 subtests passed)
helm lint chart    1 chart linted, 0 failed
```

The thirteen skipped are opt-in and were not enabled: twelve need a local Postgres or a running
zetta-tunnel (`TestConnectionRolesAgainstPostgres`, `TestEgressGatewayAgainstZettaTunnel`, the nine
`*PgxStoreAgainstPostgres` and `TestLakeSchemaEnvtest`), and
`TestLiveChartDownloadAndPrerequisiteCheck` needs `LEAF_LIVE=1` and a live cluster.

A build of this release less lake's row contract, the Airbyte removal and the `v0.1.0` agents ran
on a management cluster and its leaves, every set `Ready`. Those three changes are proven by the
suite above.

The image built from the tag is published as `oramasearch/orama-operator:v0.4.0`, and the chart as
`0.4.0`.

## Upgrading

- **Leaves:** set `version: v0.4.0` in every `config/clusters/*/operator.yaml` and apply those
  files, the first environment first.
- **The management cluster:** CRDs widened, `helm upgrade`, wait for the rollout, then apply the
  CRDs exactly ([`docs/operations/crd-rollout.md`](../operations/crd-rollout.md)).

## Installing it

- **A management cluster** is installed from `helmfile.yaml`: the platform releases first, then the
  operator chart, with its registry Secret ([`docs/install.md`](../install.md)).
- **A managed cluster** is installed by its management cluster: its `KubernetesCluster`, its
  `platform.yaml` and an `OramaOperator` at `version: v0.4.0`, applied from `config/clusters/`
  ([`docs/infrastructure/operations.md`](../infrastructure/operations.md)).
