# v0.10.6

**Released:** 2026-10-27 · **Branch:** `main` · **Previous:** [v0.10.5](v0.10.5.md) (2026-10-27).

A patch with one fix: **an App or environment is Ready only when its rollout is complete.** During a surge rollout the
old pod still serves while the new one starts, and the ready, updated and available counts all reach the desired count
then. The operator reported the App Ready, and lake's Change App split screen reloaded onto the old version. Released
with lake v0.8.1.

| Measured | Value |
|---|---|
| Resource kinds | 49 CRDs in `chart/crds` (unchanged) |
| CRD changes | none |
| Lake schema | nothing vendored |
| Tests | see [Verification](#verification) |

## What it includes

- **Ready only when the rollout is complete.** One shared `deploymentRolledOut`, as
  `kubectl rollout status` decides (desired replicas of the new template, all available, none of an old
  template left), serves the Lake's readiness (which already had the rule), `LakeApp` and
  `LakeEnvironment`.

## Upgrading

No CRD or schema change. Roll the managing cluster's operator, then every leaf's `OramaOperator` to `v0.10.6`.
Apps and environments read Ready a few seconds later than before (after the old pod is gone).
