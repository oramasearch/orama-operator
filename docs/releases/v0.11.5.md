# v0.11.5

**Released:** 2026-10-31 · **Branch:** `main` · **Previous:** [v0.11.4](v0.11.4.md) (2026-10-30).

A patch release: **Pixie's release is committed**, so the observability hubs and agents can install. Until now every
`ObservabilityHub` and `ObservabilityAgent` stayed `Pending` on `ObservabilityProvider pixie does not exist`, which is why
`ObservabilityAgentNotReady` and `ObservabilityHubUnreachable` kept firing for `orama-production-cluster-02` and `-03`.

The sample drops `cloud-plugin-load-db`, a key the operator refuses |

## What it does not include

- Any change to the operator's code, the hubs, the agents or the platform charts.
- Pixie has not run on a cluster before this release ([observability.md](../infrastructure/observability.md)).

## Upgrading

- No CRD changes. The CRD rollout ([crd-rollout.md](../operations/crd-rollout.md)) runs as for any release and changes nothing.
- **The provider is applied to the managing cluster** from `config/clusters/observability-provider.yaml`. Once it exists,
  every hub and every agent installs at once: there is no setting that holds production back while nonprod goes first.
- **What rolls on each cluster with the operator:** the operator, and the zetta-tunnel mesh pods, which carry a container
  from the operator image. No Lake or Cloud v1 workload changes.

## Known issues

- Unchanged from [v0.11.1](v0.11.1.md#known-issues).
- The managing cluster has a single node; the production hub requests about 1.8 CPU and 7 GiB of the about 2.3 CPU and 18 GiB
  free when the provider was applied.
