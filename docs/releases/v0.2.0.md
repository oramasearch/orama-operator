# v0.2.0

**Released:** 2026-10-14 · **Branch:** `main` · **Previous:** [v0.1.0](v0.1.0.md) (2026-10-12).

v0.2.0 makes the operator manage **clusters**, not only what runs inside one. A management
cluster's operator creates AKS clusters, installs their platform layer and their own operator, and
runs Lake and Orama Cloud v1 instances on them from sets, all as custom resources. The same
operator, with every kind and every controller, runs on every cluster. This release also makes
every Lake service kind start in a workspace and say why when it cannot.

Everything in [v0.1.0](v0.1.0.md) is still here. This page lists what is new or changed, and ends
with the full list of resource kinds.

## 1. Clusters as resources

- **`KubernetesClusterProvider`** (`kcp`) holds a cloud account, its credentials Secret and the
  defaults clusters are created with (#357).
- **`KubernetesCluster`** (`kcluster`) is a cluster in provider-neutral terms: region, Kubernetes
  version, node pools, a `purpose` tag (`nonprod` or `production`) and a required
  `deletionPolicy` (#357, #359).
- **`AksCluster`** (`aks`) is created by a `KubernetesCluster` whose provider is `aks`. It is the
  only kind that calls Azure, over Azure's REST API with no SDK. It creates, observes and deletes
  a cluster, and creates its resource group only when needed and deletes it only if it created it.
  Changes after creation are reported in `InSync`, not applied (#357).
- **Azure's own words in status.** `AksCluster` reads the latest operation on the cluster and
  reports its progress and any error as Azure gives it, so a quota or capacity refusal is visible
  on the resource (#362). A tag name Azure would refuse is refused before the call (#358).
- **AKS add-ons are left out** of operator-created clusters for now, by decision (#369).

Design: [`docs/infrastructure/README.md`](../infrastructure/README.md). Runbook:
[`docs/infrastructure/operations.md`](../infrastructure/operations.md).

## 2. Software on a managed cluster

- **`ClusterHelmRelease`** (`chr`) installs one pinned Helm chart on a managed cluster through its
  kubeconfig Secret. It waits for the releases it `dependsOn` and for the CRDs it `requiredCRDs`,
  can apply CRDs from URLs first (`crdURLs`), and reports the release's workloads and the first
  pod problem it finds (#364, #366). Chart hooks get a 10-minute timeout (#412).
- **`OramaOperator`** (`ooperator`) installs this operator on a managed cluster at a version. It
  pulls the chart published for that version (`oramasearch/orama-operator-chart`, private),
  applies every CRD first, waits for the prerequisites the chart names
  (`orama.cloud/required-crds`), and reports the installed version (#364, #367).
- **The platform layer** of each managed cluster (CloudNativePG, ingress-nginx, cert-manager,
  Strimzi, the ClickHouse, TiDB, K8ssandra and Valkey operators) is a set of
  `ClusterHelmRelease`s in `config/clusters/<cluster>/platform.yaml`.

## 3. Sets: instances on managed clusters

- **`LakeSet`** (`lset`) and **`OramaCloudV1Set`** (`ocv1set`) hold one template and a list of
  members. A member is one instance on one cluster, in its own namespace, with a `spec` that
  overrides only what differs (#392).
- **A set never mixes purposes.** Every member's cluster carries the same `purpose` tag; a set
  that mixes `nonprod` and `production` applies nothing.
- **Secrets travel only when listed.** A set copies the Secrets it lists from the management
  cluster into each member's namespace, and a member can override one with its own (`as`).
  Per-instance keys are never copied.
- **Members are independent.** None waits for another, and a Lake member that is not ready says
  why in the set's status (#393).
- **Removing a member** keeps the instance unless the set says `deletionPolicy: Delete`.

## 4. One operator, no differences

- **The same operator on every cluster**: the same chart, image, CRDs, RBAC and controllers. A
  cluster's role comes only from the resources on it. Every cluster gets every CRD, including the
  end-to-end test kinds that v0.1.0 installed separately (#366, #367, #368).
- **Removed:** the `--enable-cluster-management` and `--enable-e2e-controllers` flags, and the
  chart values behind them. Every controller is registered unconditionally.
- **Tests keep it so:** `TestNoClusterDiffersFromAnother`,
  `TestTheChartHasOneCRDDirectoryWithEveryKind` and
  `TestManagementKindsShipAndRunOnEveryCluster`. `TestShippedCRDValidationRulesArePlainASCII`
  catches a CRD rule an editor has rewritten with a typographic quote, which once made a CRD
  invalid (#365).
- **Two installation paths, one result.** The management cluster is installed from
  `helmfile.yaml`, and each managed cluster from its `platform.yaml` and `operator.yaml`. Both
  install the same charts at the same versions, and `cmd/platform_sync_test.go` fails when they
  differ (#433).
- **What is deployed is in the repository.** `config/clusters/` holds every cluster, platform
  release, operator and set exactly as applied, and
  `kubectl diff -R -f config/clusters/` against the management cluster is empty (#394, #395, #413,
  #430, #434, #450, #452).

## 5. Lake service kinds

Every service kind a workspace can ask for now starts in a workspace namespace under the
`restricted` Pod Security level and the workspace quota, and reports in `service_status` why it is
not ready (#429, #432, #436, #439, #441, #442, #451). Each was created through Lake on
`lake.oramadev.net` and reached `Ready`: **Postgres, Zetta, Kafka, ClickHouse, TiDB, Cassandra,
Valkey, SQLite, DuckDB and Polars.**

- **Security contexts** that satisfy `restricted` for every container the upstream operators
  create, including Strimzi's (with `STRIMZI_POD_SECURITY_PROVIDER_CLASS=restricted`), TiDB's
  slow-log tailer and K8ssandra's init containers.
- **Sizes that fit the workspace quota**, stated for each kind in
  [`docs/lake/services.md`](../lake/services.md). TiKV gets 4Gi with its block cache capped at
  512MB; with 2Gi it was OOM-killed as soon as TiDB wrote its schema (#451). Cassandra's heap is
  fixed at 1Gi (#442).
- **The workspace plan** (`defaultWorkspacePlan`) holds one service of every kind: 100 Services,
  200 Secrets, 50 pods, 20 volume claims, 100Gi of storage, 4 CPUs and 8Gi of memory requested,
  32Gi of memory limit, and no CPU limit (#439).
- **Why it is waiting**: a service's status names the refusing object and its reason (a Pod
  Security refusal, a quota, a failed StatefulSet create, a namespace warning), bounded in length.

## 6. Errors and status

- **Every error is reported**, none suppressed, and status is written with merge patches so a
  stale read cannot conflict (#361). It replaces the quieter requeue of #360.

## 7. Rules and documents

- **Pull requests target `dev`; `main` moves only on a release** (#358).
- **Nothing on a cluster is changed by hand**; the operator, or a resource it reconciles, is how
  change happens (#431).
- **Research:** secure networking for Lake (Istio, tunnels, licensing) and secure runtimes for
  apps, agents and builds, under `docs/research/` (#438, #440).
- **The clusters as applied** and the runbook for operating them: `config/clusters/README.md`,
  [`docs/infrastructure/operations.md`](../infrastructure/operations.md) (#394, #412).

## What `v0.2.0` does **not** include

- **The Orama Cloud v1 migration changes.** Juan's stack (#397–#449) is under review on
  2026-10-14; none of it is in this release.
- **A self-managed management cluster.** `orama-production-cluster-01` has no `KubernetesCluster`,
  `ClusterHelmRelease` or `OramaOperator` for itself. It is installed from `helmfile.yaml`, and
  rolling a new operator onto it is a `helm upgrade` by a script.
- **Changing a cluster after creation.** `AksCluster` reports drift in `InSync` and does not apply
  it. Node-pool kernel settings are not supported yet (#454).
- **Metering of every Lake service kind** is not verified (#435).
- **AKS add-ons** on operator-created clusters (#369).

## Known issues

- **Security: no Ingress has TLS to the origin.** On every cluster, HTTPS ends at Cloudflare's
  edge, and Cloudflare reaches the clusters through ingress-nginx unauthenticated. cert-manager is
  installed only for K8ssandra's webhooks. Every Ingress the operator creates gets a cert-manager
  certificate in #457, required before go-live.
- **ingress-nginx is retired upstream** (announced November 2025; best-effort maintenance ended
  March 2026). Every cluster pins chart 4.15.1. Its replacement belongs to #437.
- **A Lake service created before a fix does not repair itself.** TiDB Operator holds back a
  corrected pod until the cluster is healthy, which it cannot become without that pod, and
  Cassandra stalls the same way. Delete and recreate such a service (#435).
- **Leftover test resources** on the management cluster from before the end-to-end kinds were
  installed everywhere (#168).

## Installing it

- **A management cluster** is installed from `helmfile.yaml`: the platform releases first, then the
  operator chart, with its registry Secret. The steps are in [`docs/install.md`](../install.md).
- **A managed cluster** is installed by its management cluster: its `KubernetesCluster`, its
  `platform.yaml` and an `OramaOperator` at `version: v0.2.0`, applied from `config/clusters/`
  ([`docs/infrastructure/operations.md`](../infrastructure/operations.md)).
